# 每日项目论文晨报

左侧导航进入「论文晨报」，先选择所属项目，再配置时间、分类、补充关注词和邮件。每份晨报必须归属一个项目，不存在通用晨报；父项目可以涵盖子项目的方向，子项目也可另设独立晨报。项目选择器显示完整层级路径，设置与历史按项目隔离。新建配置默认关闭生成和邮件，前端默认时间为北京时间 08:00，现有配置保留原时间。关闭网页不影响调度；服务恢复后补跑当天，不批量生成过去各天。

`PAPER_CODEX_BRIEFING_CONFIG` 指定 YAML 路径（默认 `.runtime/briefing.yaml`），格式见 `deploy/briefing.yaml.example`。顶层 `projects` 数组中，每项必须有唯一的 `project_id`，最多配置 20 个项目。首次启动创建空数组，不自动启用任务。配置每分钟及手动执行前重读，无需重启或编译；无效配置在前端显示并暂停调度。前端原子保存 YAML，不保留手写注释。

旧单任务配置只有一个 `project_ids` 时兼容迁移为 `project_id`；未指定或指定多个项目的旧配置必须先明确唯一归属，不猜测目标。旧数据库表保留审计副本，历史正文、生成次数、邮件状态和邮件次数不变；启动时将无归属历史及去重记录迁到唯一配置项目。迁移不会重新生成或重发。新库按 `(project_id, day)` 唯一、按项目去重。数据库升级前应做一致性备份；升级后不可仅切回旧二进制，旧版不支持新的复合唯一键。

## 从项目规划检索

检索前读取所属项目目的、README、研究目标、项目记忆、完整子项目结构与有界的子项目 README、已有论文标题。子项目可参考祖先目的，但不读取兄弟项目对话。全局记忆只用于阅读偏好，不用全局研究兴趣改写主题。晨报 skill 将这些材料归纳为 1–12 个语义研究主题，每个主题有明确范围、项目节点映射、优先级和 1–5 个检索短语。相近目录可以合并，宽泛目录可以拆分；不按目录数分配论文配额。所有节点必须被映射，或说明是组织节点、待澄清或暂缓方向，不能静默遗漏。规划按项目材料、补充关注词和 skill 文本缓存，任一改变后重新规划。

检索限定所选 arXiv 分类，各主题独立查询、按更新时间倒序，每条路径最多 10 页 / 2000 条，整期共享 24 次页面请求预算，主题和分页间隔 3 秒。首次检查近 7 天；以后以上次本项目成功检查时间减 7 天为重叠窗口，最远回看 30 天，兼顾周末与索引延迟。按项目、规范编号、更新时间去重，只有正文实际链接介绍的论文才标记已介绍；其他项目仍可独立选入。不成功完成不会推进抓取位置。arXiv 修订/提交时间不等于公告时间，API 也可能延迟。

研究词组拆成标题/摘要中的词组合（组内 AND、组间 OR），不要求长短语逐字连续出现；明确的多词补充关注方向保留到检索中，本地相关性评分容忍词序、连字符和普通复数变化。晨报 arXiv 单次请求超时为 60 秒，不影响其他检索客户端。项目路径无候选，或发生超时、连接故障、上游 5xx 时，执行一次独立分类检索并按项目主题再筛选；不会用替代请求绕过 4xx 拒绝或限流。复查未完成、返回排序异常、空页与总数不一致、到达抓取上限均记为失败，不冒充无新增。每页及时保存总数、抓取数、窗口内数量、最新更新时间、最近请求耗时和安全错误类别；另保存去重后数量和候选数，前端「检索记录」可核验。

同一主题的近义短语只取最强匹配分，不叠加刷分；先覆盖有候选的语义主题，再按相关度和明确优先级填充余量。跨主题论文只介绍一次，没有匹配不凑数。候选最多 20 篇、全文最多 5 篇；这不是科学价值排名。检索记录分别显示每个主题的检索状态、未介绍候选、交给编辑的篇数和正文实际介绍数，预算遗漏不冒充零结果。长文在 22000 字符预算内组合引言、方法、结果与结论，并明确省略；全文不可用时依摘要。检索规划和晨报写作分开调用，缓存命中时不重新规划。模型与推理档位沿用用户配置。

### arXiv 限流与恢复

晨报和普通论文搜索共用应用进程内的 arXiv 串行通道，最多一个请求进行中、相邻请求至少间隔 3 秒，覆盖读取响应正文的整个过程。不能约束同一机器上的其他应用或共享代理出口上的其他用户，因此守住本地频率也不保证上游不会返回 429。依据：[arXiv API 使用限制](https://info.arxiv.org/help/api/tou.html)。不修改代理路由、不轮换出口、不用备用查询绕过限流。

429 不做请求内快速重试；读取 `Retry-After` 的秒数或 HTTP 日期，冷却时间至少为 15、30、60、120 分钟的递增退避并加入少量随机延迟，服务端要求更久则完整遵守。带 `Retry-After` 的 5xx 同样等待，不立即换查询。全应用共享冷却记录，保存在工作区 `.paper-wiki/arxiv-cooldown.json`，重启仍有效；冷却期间手动补跑被拒绝，不增加尝试次数。其他临时失败的任务级重试从 10 分钟增至 20 分钟，每项目每天仍最多自动尝试 3 次，不能靠重试绕过上限。

检索记录保留 HTTP 状态、冷却截止、服务端等待时间、允许列表中的服务/缓存响应头和错误正文类别；不保存任意响应正文、cookie、认证头或请求 URL。网页显示“arXiv 限流”和可重试时间，区分实际联网与被冷却机制拦截。旧记录没有这些响应头，不能倒推出当时的具体限流规则。

同一期晨报、完全相同查询/窗口/分页的已验证页面可在 90 分钟内从 `.paper-wiki/briefing-fetch/` 复用，失败、异常空页和未通过校验的结果不缓存；前端明确标记复用页数，不声称重新实时获取。即使是首次生成，也按本期第一次启动时间固定窗口。重试仍重新核验日期和总数，完整生成前不推进“已介绍”游标。应用自建的哈希命名页面缓存超过 7 天后清理，不删除论文、晨报正文或其他用户文件。

## 晨报 skill 与热更新

默认 skill 随应用安装到工作区 `.codex/skills/project-morning-briefing/`：`SKILL.md` 定义工作方式，`references/planning.md` 负责研究规划，`references/editorial.md` 负责编辑写作。两次模型调用分别加载对应阶段的说明。可以直接修改工作区里的 Markdown，下一次生成重新读取，不用编译或重启；服务初始化不会覆盖已存在的自定义文件。修改规划说明会使规划缓存失效。生成与投递的边界、请求上限及错误处理仍由应用执行，修改写作偏好不会额外授权发信或导入论文。

## 正文和图文邮件

开头直接给阅读判断和具体工作名称；栏目按研究主题、关键问题或跨方向进展组织，不固定照抄项目树。深读通常 1–3 篇，保留完整题名、作者、机构、问题、方法、实验结果、阅读判断及限制；速览通常 4–6 篇，候选不足不凑数，也不为了压字数把多个方向挤掉。明确区分作者结果与编辑判断，说明与项目方向的关系。信息完整优先于机械字数限制，不因格式不完美丢弃正文。有相关候选却未在正文介绍的方向会追加覆盖提醒；含义待澄清或暂缓的方向也明确说明，避免把未覆盖说成没有新增。

机构和图示以官方 arXiv HTML/已有正文为依据，不猜测机构、不用替代图。有限获取并缓存 HTML 元数据，优先 teaser/总览单图，缺少时如实说明。邮件正文以受限官方来源的 `<img src="https://…">` 显示原图，不使用 CID 附件；点击可看大图。邮箱可能要求允许加载图片。扁平单层排版减少手机边距，不逐层嵌套卡片。HTML 预览与发送共用渲染模板，无脚本权限，不触发发送；另保留完整纯文本备用版。

正文和状态持久化后再尝试归档到所属项目对话，归档失败不丢正文、不阻止邮件。历史列表返回最近 300 份，前端按项目筛选。启用邮件后，无符合方向的新论文也发送「暂无新增」状态简报；最终失败发送异常通知，明确不等于没有论文。不逐次发送临时重试通知。临时失败采用递增退避并遵守上游冷却时间（见上节），每项目每天自动尝试最多 3 次；模型拒绝、认证等永久错误不自动重试，避免流量风暴。达到上限后可手动补跑失败任务，但不重置自动重试额度。每轮重试在设置快照的 attempt_history 保存上一轮诊断、错误、时间和投递状态，累计尝试数不清零；新一轮邮件使用独立的投递计数与 Message-ID。尚未发送的空结果可以手动重新检索，已完成内容不重复生成；投递中或结果不确定时拒绝重新生成。总超时可配置 2–30 分钟，默认 15 分钟。各项目顺序生成，避免同时占用大量资源。

## 从晨报加入项目

正文下方勾选论文，选择目标项目/子项目后点击加入。默认目标为晨报所属项目，但可以改选其他项目。已有论文只增加项目关联，不重复下载；新论文进入既有导入队列，界面显示正在导入、已加入或失败原因。只允许选择本期正文引用、且保存在证据快照中的论文，不信任客户端传入任意地址。生成晨报不会自动导入论文。

## 邮件凭据和发送保障

`PAPER_CODEX_BRIEFING_MAIL_ENV` 指向本地 dotenv 文件，支持 `MAIL`、`PASSWD`，以及可选 `SMTP_HOST`（默认 smtp.qq.com）、`SMTP_PORT`（默认 587）。Python 3 标准库通过 STARTTLS 发送并验证证书。密钥不进 API 或 Git；建议凭据文件权限 600。修改文件内容无需重启，改变环境变量路径需要重启。

每份邮件最多尝试 3 次；临时故障等待 10 分钟，授权或正文明确拒收时停止自动发送。邮件使用独立重试时间 `mail_next_attempt_at`，不会修改生成重试计划；永久生成失败的通知邮件重试也不会重新调用模型。发送中断或重启而无法确定 SMTP 是否接收，标记「发送结果待确认」，须检查邮箱后手动决定。已发送不再发送，邮件失败不会重新生成晨报。SMTP 接收不等于最终进收件箱。邮件主题含日期和项目名以及无新增/异常类型，收件人按各项目当前配置读取。异常通知不复制上游原始错误或密钥信息，仅提示在已登录网页查看诊断。
