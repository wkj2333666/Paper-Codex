# 每日论文晨报

左侧导航「论文晨报 → 设置」开启每日生成，默认北京时间 09:30。晨报是独立栏目，不再嵌入工作台；设置、历史正文、生成和邮件状态都在该栏目中。窄屏打开左侧导航也可进入，支持浏览器前进/后退和刷新后恢复。调度由服务器执行，关闭网页不影响运行。错过时间会在服务恢复后补跑当天一次，不批量补发过去的邮件。

`PAPER_CODEX_BRIEFING_CONFIG` 指定 YAML 路径（默认 `.runtime/briefing.yaml`），示例见 `deploy/briefing.yaml.example`。配置每分钟和每次手动执行前重新读取；无效配置在晨报栏目显示错误，暂停调度。首次启动默认关闭。UI 保存原子替换 YAML，不保留手工注释。

`PAPER_CODEX_BRIEFING_MAIL_ENV` 指向本地 dotenv 文件。邮件由 Python 3 标准库发送，凭据仅支持 `MAIL`、`PASSWD`，可选 `SMTP_HOST`（默认 smtp.qq.com）、`SMTP_PORT`（默认 587）。支持单/双引号包裹的值，不支持变量展开和多行密钥。必须提供 STARTTLS；证书验证开启。不要把凭据文件提交 Git。服务用户需有读取权限，建议文件权限 600。修改凭据本身无需重启；改变环境变量路径需要重启服务。

检索限定配置的 arXiv 分类，按更新时间倒序，每次最多 2000 条、分页间隔 3 秒。首次检查近 4 天；后续以上次成功检查时间减 2 天为重叠窗口。按 arXiv 规范编号 + 更新时间去重；检查成功后未匹配/超出篇数上限的论文也标记已检查，之后修改关注词不回填这些旧记录。未成功完成不会推进去重位置。arXiv 首次提交时间、修订时间不等于每日公告时间；API 可能延迟，因此不保证运行时包含刚刚公告的全部论文。

按关注词筛选，具体方向词和标题命中优先于 robot 等宽泛词，分数相同按更新日期排序；这只是相关度初筛，不代表科学价值排名。候选池最多 20 篇，最多为 5 篇取得全文。短文保留完整可用文本；长文在 22000 字符预算内组合开头、方法、实验/结果、讨论/结论及参考文献之前的尾部，片段之间明确标记省略；无章节标题时按正文位置取样。全文不可用时使用摘要。证据仍有覆盖限制，不声称完整阅读未提供的内容。

生成采用一次模型调用，参考所选项目目标与已保存兴趣，不读取其他对话正文。模型先在内部比较候选与证据，再按晨间阅读层次写作：开头「30 秒速览」最多 3 个判断；「今天最值得读」精选 1–3 篇（证据不足可不选），每篇突出变化、判断与关键限制；剩余最多 4 条短讯，不凑数；结尾给一个具体阅读动作。通常目标 900–1400 个中文阅读字量，只有 1–2 篇候选时目标 400–800，约 3–5 分钟按需阅读。这是生成指导而非机械截断；不会因篇幅/格式不符丢弃模型正文。明确区分作者结果与编辑判断，注明证据层级和旧稿修订，不臆测版本差异。

界面中的「最多候选论文数」仍对应 YAML `max_papers`；「深读候选数」对应 `fulltext_papers`。这些是筛选/证据预算，不是必须写满的篇数。新流程只作用于后续生成，不覆盖历史晨报，不重复发送已有邮件。不自动导入正式论文库。模型使用当前默认设置，不修改用户档位。模型生成超时 2–30 分钟（默认 15），失败等待 10 分钟后重试，每天最多 3 次。

正文、证据快照、生成状态和邮件状态分别持久化。历史列表显示最近 60 份。仅选择一个参考项目时，正文另存为该项目的普通对话，可以从 Codex 历史继续追问；所有晨报均保存在晨报栏目，不选或选择多个项目时不创建跨作用域对话。先持久化正文，再执行可选的对话归档，归档失败不丢正文、不阻止邮件。没有匹配的新论文只记录空状态，不发邮件。

邮件以 `multipart/alternative` 发送：支持 HTML 的客户端优先显示带内嵌样式的排版，另附完整纯文本备用版。标题、列表、加粗、代码块、表格和论文链接正常排版；不运行脚本，不自动加载外部图片（图片改为链接）。客户端可能调整颜色或字体，尤其是在强制深色模式下。

邮件最多尝试 3 次，临时失败等待 10 分钟；授权或邮件正文被明确拒收时暂停自动发送。发送途中断线、超时或服务重启，可能已经被 SMTP 接收，标记「发送结果待确认」，必须检查邮箱后手动决定重发。已发送的晨报不重复发送；SMTP 接收不等于最终进入收件箱，请同时检查垃圾邮件。邮件故障不重新调用模型。
